# Content Pipeline

## Overview

The runtime system answers from a structured story index that is prepared before playback. For Sintel the index was written by hand from the film's frames, not generated by a model. The first attempt at an automated or semi-automated index was partly invented and was thrown away on 2026-10-14 (see `friction-log.md`), so the working rule is: describe only what you can see in the frames, and check every event against an independent frame grab.

```
source video
     |
     v
HLS packaging (ffmpeg)            frame extraction (ffmpeg, 1 frame / 3 s)
                                          |
                                          v
                           contact sheets, viewed in order
                                          |
                                          v
              scenes, events, clues, characters, objects, story states
                                          |
                                          v
                        validate (script) + spot-check against ffmpeg frames
```

## Output Structure

```
content/sintel/
  metadata.json
  scenes.json        16 scenes
  events.json        28 events
  clues.json         7 clues
  characters.json    6 characters
  objects.json       7 objects
  story-state.json   12 story states
  frames.json        238 frames
  subtitles.json     empty (the film has no dialogue)
  ANALYSIS_NOTES.md  method, timing offset, spoiler gating, spot checks
  frames/            seq_0001.jpg ... seq_0238.jpg   (not committed, see below)
  sheets/            contact sheets                  (not committed)
  accuracy/          ffmpeg vs app frame comparisons (not committed)
```

`content/last-signal/` is an older fictional index used as a test fixture; it is not the demo.

## 1. Metadata

`metadata.json` has the content ID, title, duration and notes. For Sintel:

```json
{
  "contentId": "sintel_001",
  "title": "Sintel",
  "type": "movie",
  "durationMs": 712958,
  "language": "en",
  "frameIntervalMs": 3000,
  "sceneCount": 16
}
```

(abridged; the real file also has a description, genre, an empty `subtitleTracks` list and notes). The index is timed to a copy of the film that is 712.96 s long, 1920x818, with no audio track.

## 2. Subtitles

Sintel has no dialogue and the copy used has no audio, so `subtitles.json` is empty. For a film that has a WebVTT file, `scripts/ingest_subtitles.ts` (run as `npm run ingest:subtitles` in `backend/`) parses it deterministically: timestamps, formatting tags, merging tiny consecutive cues, speaker metadata. No LLM is involved. This path is not exercised by the Sintel demo.

## 3. Frames

Frames are extracted at one every 3 seconds, 640 px wide:

```bash
ffmpeg -i sintel.mp4 -vf "fps=1/3,scale=640:-1" -q:v 3 content/sintel/frames/seq_%04d.jpg
```

This gives 238 frames for the 712.96 s film. Two things to know:

- **The file number is not the time.** `seq_NNNN.jpg` shows film time `(NNNN-1)*3 + 1.5` s, not `(NNNN-1)*3` s, which is what `frames.json` records. (Measured by PSNR against ffmpeg frames for six frames.) The index compensates: each event's `timestampMs` is set so the frame nearest to `timestampMs + 1.5 s` is the shot its caption describes, and the backend aims 1.5 s after an event when it picks a frame.
- **The images are not in the repo** (`content/*/frames/*.jpg` is gitignored). Regenerate them with the command above. The visual recap shows blank slides without them.

Frames feed the visual recap montage. They are not sent to the AI provider; the prompt is text only.

`scripts/build_sheets.js` makes 4x4 contact sheets with timestamp labels for reviewing the frames. It runs `ffmpeg` from PATH (or `FFMPEG`) and uses `drawtext` with an explicit Windows font file. `scripts/extract_frames.ts` is an earlier interval-based extractor that does not produce the `seq_NNNN` names the index uses. 

## 4. Scenes

16 scenes, each with start and end times, title, summary, characters, locations, important objects, event and clue IDs, and questions raised and resolved. They were cut by watching the contact sheets in order, with extra 1 fps extractions where precision mattered.

A scene summary can describe moments later in the same scene, so recaps never print raw scene prose. They are built from events (below). Scene 15 starts at 605 s, so Scales is deliberately left out of its character list; it would otherwise appear next to "Adult Dragon" before the reveal.

## 5. Events

Events are the atoms of the story. Each has:

- `timestampMs`
- `type` (`character_action`, `dialogue`, `clue`, `reveal`, `relationship_change`, `object_change`, `location_change`)
- `description`: what is literally on screen (grounding)
- `story`: a short narrative beat shown to the viewer in recaps and the visual montage
- characters and objects involved
- `importance` (0.0 to 1.0); recaps only pick events at 0.5 or above
- `spoilerBoundaryMs`: the position from which the event is safe to mention

Story lines interpret the shots as plot but stay within what the frames support.

## 6. Clues, characters, objects, story states

Clues have a `discoveredAtMs`. Character facts have a `knownAtMs`; object state changes have timestamps; story states are snapshots at a time. All are filtered by the viewer's position.

The twist (the dragon Sintel kills is Scales, grown up) plays at about 10:06. The events, the clue and the character facts that state it are all gated to 622 s (10:22), after the beat has finished playing.

## 7. Validation

```bash
cd backend
npm run validate:content -- ../content/sintel
```

Checks required fields, valid timestamps, and cross-references (scene IDs, character names). It reports 0 errors and 0 warnings for Sintel as of 2026-10-20. It does not check the index against the film: that was done by viewing, for each of the 28 events, the ffmpeg frame at `timestampMs + 1.5 s` next to the frame the app shows (see `ANALYSIS_NOTES.md`).

## Quality Over Automation

For the hackathon film, hand correction is the method, not a fallback. The goal is a story index that is right about the film, not a fully automated pipeline. Adding a second title means repeating this work.
